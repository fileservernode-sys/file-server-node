Category 01

Getting Started: Step-by-Step Setup Guide

Follow these 8 steps to commission your Android smartphone into a working file server.

Provisioning Sequence

  1. Create Your Account: Navigate to zdexcloud.com/pages/get-started.html. Enter your email and verify the 6-digit OTP sent to your inbox.
  2. Download Android App: Download the official ZdexCloud APK onto your dedicated Android smartphone (running Android 8.0 Oreo or higher).
  3. Sign In on Android: Launch the app and sign in with your verified account email and password.
  4. Link Hardware Node: The application automatically provisions a hardware-bound installationId in Android Keystore, pairing the phone to your account.
  5. Grant Permissions: Grant "All Files Access" / storage permissions and notification permissions when prompted.
  6. Name Your Server: Assign a distinct, recognizable server label (e.g. "Living Room Server", "Studio Backup").
  7. Start Server Mode: Set a dedicated server password and tap "Start Server". Confirm the state becomes RUNNING.
  8. Access Remotely: Open zdexcloud.com/pages/dashboard.html on your PC or tablet, click your server, enter the server password, and begin managing files!

Prerequisites Checklist

  • Dedicated Android Phone: Android 8.0 (API level 26) or higher with at least 1.5 GB RAM.
  • Continuous Power: Standard 5V USB wall charger to keep the phone powered permanently.
  • Stable Network: 2.4GHz / 5GHz Wi-Fi network with internet access.
  • Storage Medium: Sufficient internal flash memory or an inserted Class 10 / UHS-1 micro-SD card.
  • Modern Web Browser: Google Chrome, Mozilla Firefox, Apple Safari, or Microsoft Edge on your computer or tablet.
Category 02

Android Server Operations & System Policies

Understanding permissions, foreground services, notifications, and battery optimization.

Permission / Setting Why ZdexCloud Needs It Impact If Denied
All Files Access (Storage) Allows the local server engine to index, read, upload, and stream files from /storage/emulated/0 and micro-SD cards. Server cannot read or write user files; file manager will show empty directories.
Foreground Service (FOREGROUND_SERVICE) Keeps the local HTTP loopback engine and outbound WebSocket alive while the phone screen is locked or sleeping. Android OS terminates the server process after a few minutes of screen-off time.
Post Notifications (POST_NOTIFICATIONS) Android 13+ requirement to display the persistent server status notification necessary for foreground execution. Foreground service status cannot be established; server may be killed by OS.
Battery Optimization Whitelist Exempts ZdexCloud from Android Doze mode, preventing network socket suspension when the phone is stationary. Outbound socket pauses during sleep; remote browser experiences connection timeouts.

How to Keep the Server Continuously Available

To optimize for continuous, unattended background operation:

  • Keep the device plugged into AC power using a standard 5V wall adapter.
  • In phone Wi-Fi advanced settings, set "Keep Wi-Fi on during sleep" to Always.
  • In Settings > Apps > ZdexCloud > Battery, select Unrestricted.
  • On OEM builds (Xiaomi, Samsung, Huawei), lock the app in the Recent Apps view and enable "Autostart".
  • Place the phone in a shaded, ventilated area to prevent thermal throttling.

Remote File Manager Operator Guide

How to perform file management, media streaming, and directory operations remotely.

Directory Navigation

Use breadcrumbs to navigate nested folder trees. Click category shortcuts (Photos, Videos, Docs, Audio, Archives) for instant filtered views of your media.

File Uploads & Downloads

Drag & drop files into the upload modal to transfer files to your phone. Click the download icon on any file to stream it directly to your computer.

Category 04

Networking Architecture, WSS & CGNAT

How outbound WebSocket tunnels eliminate port forwarding and traverse restrictive firewalls.

Outbound TLS 1.3 WebSocket Tunnel

When Server Mode starts, the phone executes an outbound TCP handshake over secure port 443. Once authenticated via its unique connection token, the duplex tunnel stays open:

  • Zero Open Ports: Your home router requires no forwarded ports or static IP bindings.
  • Stateless Buffer: The gateway receives RPC requests from your browser and pushes them down to the phone's open socket in RAM.
  • Zero Disk Writes on Relay: Gateway memory buffers streaming chunks; zero file bytes are written to disk.

Carrier-Grade NAT (CGNAT) Compatibility

Most mobile network providers (4G/5G) and fiber ISPs deploy CGNAT, sharing one public IPv4 address among hundreds of subscribers:

  • Why CGNAT Breaks Old Servers: Inbound port requests cannot route to your specific router.
  • Why ZdexCloud Works: CGNAT fully allows client-initiated outbound connections. Because the phone dials out, the tunnel establishes reliably.
Category 05

Multi-Device Fleet Management

Managing up to 5 physical Android servers under a single user account.

Fleet Limits & Identity

  • 5 Server Cap: Each ZdexCloud account can register and run up to 5 active physical phone servers.
  • Persistent Identity: Each device generates its own hardware-bound installationId stored in Android Keystore.
  • Independent Passwords: You can assign different server passwords to each phone for layered security.

1-Click Server Switching

  • Open the server selector dropdown in the top header of the web file manager.
  • Switch between your servers (e.g. "Home Vault", "Office Node", "Travel Phone") instantly.
  • Each server session is independently managed without logging out of your central account.
Category 06

Security, Privacy & Authentication Session Policy

Understanding credential separation, transport encryption, and our strict 24-hour session model.

Strict 24-Hour Authentication Session Model

For security hygiene and compliance with modern enterprise standards, ZdexCloud enforces a strict 24-hour absolute session lifetime:

  • When you sign in with Email and 2FA OTP, your session token is valid for exactly 24 hours.
  • Sessions are not extended indefinitely by background activity.
  • After 24 hours, the session expires and you must sign in again with your credentials.
  • Server Independence: Your Android phone server continues running uninterrupted in the background regardless of whether your web browser session has expired.

Account Credentials vs. Server Passwords

Access is protected by two distinct, decoupled security boundaries:

  • Platform Account (Email + 2FA OTP): Controls device pairing, account settings, and discovery.
  • Server Password: Stored locally on the phone to authenticate remote file operations. Even if an account were compromised, the attacker cannot unlock server files without the distinct server password.

Backup Recommendation: The 3-2-1 Rule

ZdexCloud turns your hardware into a high-utility personal file server for remote access, sharing, and streaming. It is not an automated offsite cold-disaster backup service. If your phone suffers physical damage, water damage, or hardware failure, files stored solely on that device could be lost. We strongly advise following the 3-2-1 backup rule: keep 3 copies of important data on 2 different media types, with 1 copy stored in an independent cold or offsite location.

Troubleshooting Knowledge Base

Diagnostic steps and solutions for common operational symptoms.

Symptom 1: Server shows "OFFLINE" in the Web Dashboard

Likely Cause: The Android phone lost power, disconnected from Wi-Fi, or the Android OS suspended the background process.

What to Check: Verify the phone is plugged into power, connected to Wi-Fi, and the ZdexCloud app status shows "RUNNING".

Expected Result: Once network connectivity is restored, the phone reconnects to the gateway within seconds and displays "ONLINE".

Symptom 2: Server stops running when screen is locked or sleeping

Likely Cause: Android Doze mode or manufacturer power saving terminated the background service.

What to Check: Open Android Settings > Apps > ZdexCloud > Battery and verify it is set to Unrestricted. On Xiaomi/Samsung phones, enable "Autostart".

Expected Result: The foreground service maintains active server operation continuously while the screen is locked.

Symptom 3: "Invalid Server Password" error in web file manager

Likely Cause: Entering your platform account password instead of the dedicated server password set on the phone.

What to Check: Confirm the password entered matches the server password configured inside the Android app on the host device.

Expected Result: Successful authentication unlocks the web file manager immediately.

Symptom 4: "Session Expired" notification after 24 hours

Likely Cause: Normal behavior under our strict 24-hour absolute session security model.

What to Check: Simply log in again with your email and 2FA OTP code.

Expected Result: A fresh 24-hour session is issued and your servers remain available.

Symptom 5: Remote upload or download fails mid-transfer

Likely Cause: Wi-Fi instability on the host phone or upstream bandwidth saturation.

What to Check: Verify phone Wi-Fi signal strength and available storage space on the device.

Expected Result: Retrying the transfer over stable Wi-Fi completes successfully.
