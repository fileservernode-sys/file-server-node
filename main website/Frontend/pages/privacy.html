Data Protection & Architectural Transparency

ZdexCloud Privacy Policy

Last updated: September 2026. This policy explains how ZdexCloud handles account and device metadata, establishes physical on-device storage boundaries, and protects user data.

Physical On-Device Storage: Our Core Privacy Principle

ZdexCloud operates a control plane and secure relay gateway. Your Android smartphone remains the physical storage host for personal files you configure the server to expose. Unlike conventional cloud storage providers, ZdexCloud does not act as a central storage host for your documents, media, or archives.

1. Overview & Scope of This Policy

This Privacy Policy applies to the ZdexCloud website (zdexcloud.com), the web platform dashboard, the backend platform services, the secure connection service, and the ZdexCloud Android application.

This policy explains what information is collected, how it is processed to deliver personal server connectivity, what information remains strictly on your personal hardware, and the safeguards we maintain.

2. Architectural Storage Distinction: Platform Data vs. User Files

To understand your privacy on ZdexCloud, it is essential to distinguish between two distinct categories of data:

Platform Control Plane Data

Includes your account credentials, email address, registered device identifiers, pairing metadata, session tokens, and security audit logs. This metadata is stored in our secure database to manage authentication and server discovery.

Device-Hosted File Data

Includes your personal documents, family photographs, audio, video, and directories. These files reside physically on the internal flash memory or microSD card of your Android phone. They are not stored in our database.

3. Information Associated With Your Account

When you create an account on ZdexCloud, we collect:

  • Email Address: Used as your primary account identifier for login, security notifications, two-factor authentication, and password recovery.
  • Full Name (Optional): Provided during registration for personalized communications.
  • Cryptographic Password Hash: We never store plaintext passwords. Passwords are transformed using standard cryptographic one-way hashing algorithms before storage.
  • Account Status & Timestamps: Verification status, registration timestamp, and last profile update timestamp.

4. Information Used During Authentication & Session Security

ZdexCloud enforces robust authentication policies to protect against account takeover and session hijacking:

  • One-Time Verification Codes (OTP): 6-digit numeric codes generated for registration verification, login 2FA, and password resets. OTP codes are stored temporarily with an expiration limit of 10 minutes and invalidated upon use.
  • Strict 24-Hour Absolute Session Lifetime: Web platform sessions are governed by an absolute 24-hour expiration policy. Active browser use does not extend or slide this lifetime indefinitely; after 24 hours from initial authentication, the session strictly expires and re-authentication is required.
  • Security Audit Logs: We record authentication audit events (such as successful logins, failed attempts, and password reset requests) along with timestamps to protect against brute-force attacks.
  • Credential Separation: Your web platform account credentials are decoupled from your on-device file-server credentials. Dedicated file-server credentials configured in the Android app are stored locally on your device and are not uploaded to our central database.

5. Device and Server Registration Information

To enable your Android device to register as a discoverable file server, we store:

  • Installation Identifier: A persistent unique identifier generated by the application installation to bind the phone server to your account and prevent multiple conflicting registrations from the same hardware.
  • Hardware & System Metadata: Device model, platform, Android OS version, and application version to verify compatibility.
  • Server Instance Metadata: User-defined server name, server operational status (Running, Stopped, Error), start timestamp, and last recorded heartbeat timestamp.

6. Information Related to Remote Connections & Gateway Relay

When accessing your phone server remotely through the web file manager:

  • Outbound WebSocket Tunnel: Remote access is facilitated via an outbound TLS 1.3 WebSocket tunnel established by the Android app to our relay gateway. This architecture avoids requiring inbound router port forwarding on your home network.
  • Ephemeral Routing Tokens: Short-lived gateway connection tokens are issued to authenticate client browser sessions with the phone's relay tunnel.
  • In-Flight Byte Forwarding: The relay gateway acts as a bridge for encrypted file transfers and media streaming. File payloads traverse memory buffers in flight and are not written to persistent disk storage on our servers.

7. Files and Storage Custody

Your personal files remain your own:

  • User-Configured Scope: You choose which directories the Android server exposes via system file permissions.
  • No Central Content Indexing: ZdexCloud does not index file contents, scan documents for marketing profiles, or analyze personal photos.
  • Device Lifecycle Independence: The Android server runs as a background foreground service independently of your web browser sessions. Logging out of the website does not erase or disrupt files stored on your phone.

8. Website Usage Information & Cookie Transparency

We maintain minimal, privacy-preserving website operations:

  • Diagnostic Server Logs: Standard HTTP request logs (IP address, user agent, request path, timestamp, response code) are processed temporarily for diagnostic monitoring and DDoS prevention.
  • Zero Advertising Trackers: We do not load third-party marketing trackers, behavioral profiling scripts, or advertising networks.
  • Essential Session Storage: Web browser sessions utilize standard client-side tokens required strictly to maintain your authenticated login state.

9. Email Communications & Push Notifications

We transmit only functional and security-related communications:

  • Transactional Email: Registration OTP codes, login verifications, and password reset instructions are dispatched via Brevo (HTTPS REST API / SMTP relay). Only your email address, recipient name, and temporary code are transmitted for delivery.
  • Push Notifications: Server connectivity notifications (e.g. server offline or reconnection alerts) are dispatched to registered Android devices via Google Firebase Cloud Messaging (FCM). Push tokens can be disabled in the app settings.

10. How Information Is Used

We use collected information strictly to:

  • Authenticate your account and maintain active 24-hour web platform sessions.
  • Facilitate discovery and encrypted WebSocket relay connections between your browser and registered phone servers.
  • Enforce plan boundaries (e.g. 1 registered server on Free, up to 5 on Pro).
  • Investigate and prevent unauthorized access, credential abuse, and network attacks.
  • Respond to support requests initiated by you.

11. How Information Is Protected

We implement defensive, verified architectural safeguards:

  • Transport Security: All web dashboard and gateway relay communications utilize TLS 1.3 encryption in transit.
  • Outbound Tunneling: Your home router requires zero open incoming ports, protecting your local network from external scanning.
  • Strict Session Timeout: Web platform sessions expire strictly after 24 hours to prevent persistent session hijacking.
  • Rate Limiting & Hashing: Sensitive authentication endpoints enforce rate limiting, and passwords are cryptographically hashed.
  • Realistic Security Stance: While we employ industry-standard defensive practices, no electronic transmission or storage system can guarantee absolute security. Users must protect their own devices and credentials.

12. Service Providers & Third Parties

We do not sell, rent, or trade your personal data to third-party data brokers or advertisers. We share information only with technical infrastructure providers necessary to operate the service:

  • Brevo: Transactional email delivery service for OTP verification codes and security notices.
  • Google Firebase Cloud Messaging (FCM): Push notification relay for Android server status notifications.
  • Cloudflare: Reverse proxy and DNS edge routing for DDoS protection and transport security.

13. Data Retention Policies

We retain information only as long as necessary to provide platform services:

  • Account & Device Records: Maintained for the duration of your active platform account.
  • One-Time Passwords (OTP): Expire automatically after 10 minutes and are deleted or marked used immediately upon consumption.
  • Web Session Tokens: Expire strictly after 24 hours from creation.
  • Audit & Operational Logs: Retained for security diagnostics, rate limiting, and anomaly detection before periodic rotation.

14. Account Deletion & User Rights

You maintain control over your personal data:

  • Account Deletion: You may request deletion of your platform account at any time by contacting support@zdexcloud.com. Upon deletion, your account profile, device pairings, and session tokens are purged from the control plane database.
  • Local Files Preserved: Because your personal files reside physically on your Android phone, deleting your ZdexCloud platform account does not delete files from your phone's hardware.

15. User Security Responsibilities

Personal cloud security is a shared responsibility:

  • Device Physical Security: Maintain physical custody and screen-lock protection on the Android phone operating as your file server.
  • Strong Credentials: Use a strong, unique platform password and distinct file-server credentials. Never disclose your password or OTP to anyone.
  • Independent Backups: Because a single phone represents a single physical node, users must maintain independent backups (such as the 3-2-1 backup rule: 3 copies, 2 media types, 1 offsite copy) for all mission-critical data.

16. Children's Privacy

ZdexCloud is designed for general audiences and is not intended for use by children under the age of 13 (or the applicable legal age of digital consent in your jurisdiction). We do not knowingly collect personal information from children.

17. International Access & Geographic Custody

ZdexCloud services are accessible globally via the internet. Because your personal files are physically hosted on the Android smartphone you configure, the geographic custody and physical storage location of your files remain wherever you choose to maintain your physical phone hardware.

18. Changes to This Privacy Policy

We may update this policy periodically to reflect architectural changes or regulatory updates. Any revisions will be published on this page with an updated "Last updated" date. We encourage users to review this page periodically.

Direct Privacy Answers

Frequently Asked Privacy Questions

Direct, authoritative answers regarding data storage, session security, and personal file custody.

Where are my ZdexCloud files stored?

Your files are stored physically on the internal flash storage or microSD card of the Android phone you configure as your server.

ZdexCloud does not copy or store your personal files on central platform cloud servers. Physical custody remains entirely on your own smartphone hardware.

Does ZdexCloud upload my files to cloud storage?

No, ZdexCloud does not upload your personal files to central corporate cloud storage servers.

When you access files remotely, data streams through an outbound encrypted WebSocket relay tunnel directly from your phone to your browser without being stored on central platform disk storage.

Does ZdexCloud require router port forwarding?

No, ZdexCloud requires zero router port forwarding, zero dynamic DNS setup, and zero public IP exposure.

The Android application initiates an outbound TLS 1.3 connection to our gateway relay, allowing remote access while keeping your home router ports completely closed.

How long does my ZdexCloud web session last?

Web platform dashboard sessions last for a strict absolute lifetime of 24 hours from login.

Active browsing does not slide or indefinitely extend this window. After 24 hours, the session strictly expires to protect against session hijacking, requiring re-authentication.

Is my Android server affected when my web session expires?

No, your Android phone server continues running continuously in the background independently of web dashboard logins or session expirations.

The phone server operates as a persistent Android foreground service. When your 24-hour web session expires, only your browser access requires re-login; the phone server remains online.

What information does ZdexCloud collect?

ZdexCloud collects only essential platform metadata: your email, cryptographic password hash, device hardware model, server names, and connection status.

We do not collect or store your private files in our database, and we do not use third-party advertising cookies or cross-site tracking scripts.

Can I use my own Android phone as the storage host?

Yes, that is the primary purpose of ZdexCloud. You provide the Android phone (Android 8.0+) as your self-hosted hardware storage host.

You configure which folders the phone exposes, giving you complete physical custody over your storage media without monthly storage fees.

Should I back up files stored on my Android server?

Yes, you should always maintain independent backups of critical data stored on your phone server.

Because a single smartphone represents a single physical node that can experience hardware failure, battery degradation, or damage, users must follow a 3-2-1 backup strategy for irreplaceable files.
